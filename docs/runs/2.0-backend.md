### Findings that change the build
1. E2B sandboxes lack `xt_owner`: the inner fence uses nftables `meta skuid 1001`, not iptables.
2. npm 11 skips dependency install scripts unless allowed: detonation sets
   `npm_config_dangerously_allow_all_scripts=true`, and the template build asserts a dependency postinstall runs.
3. E2B domain filtering works on SNI/Host only for 443/80 and keeps 8.8.8.8 DNS open: the outer fence is
   registry-only, the inner fence redirects all uid-1001 TCP and DNS to the forge.
4. `scripts/apply-migration.mjs` hardcodes the production project ref: replaced by a branch-only script.
5. Supabase MCP has no permission on this project; the CLI reaches the branches API.
6. No Docker or psql locally: migration round-trips use PGlite in `npm test` plus a Supabase branch.
7. Pre-2.0 verdict word for 80 to 89 contains a banned word; 2.0 verdict words are fixed in DESIGN.md 5.5.

### Decisions recorded for later steps
1. `score.ts` treats a skipped install the same as a failed one (cap 74): no install means no observed behaviour.
2. Base 85 with reputation bounded at +5 means a score of 90 needs both `owner_established` (+3) and more than 100k weekly npm downloads (+2). A GitHub repo target has no download signal, so its ceiling under the section 5.3 formula is 88 ("Low risk"). The formula is implemented exactly as written; the lead decides whether section 5.3 changes.
3. Forge contract for step 3: registry traffic served from the mirror must carry `forged_kind` `"mirror"` or `"registry"` (`REGISTRY_FORGED_KINDS` in `score.ts`); any other record to a registry host is scored as contact.
4. `cr-yara.py` output contract for step 3 is the JSON shape in the `lib/engine/static/scanners.ts` header.
5. Test-only stand-ins added in this step: `tests/support/scripted-model.ts` (validates every canned value with the request schema). The orchestrator-level `stand-in-model.ts` and `mock-sandbox.ts` remain step 4 work.
