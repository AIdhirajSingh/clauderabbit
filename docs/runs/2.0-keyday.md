### Realtime design

Realtime Broadcast from the database: the v2 trigger calls `realtime.send(payload, type, 'scan:<run_id>',
false)` (public channel). Broadcast needs no exposed schema, so `v2` stays out of the Data API and no project
config change is needed. Live clients of `/api/scan` already get every event on the NDJSON / SSE stream; the
`realtime_channel` field names the topic for any subscriber.

### Design as built

Jev (`lib/engine/model/jev.ts`, `lib/engine/model/checks.ts`)
- `GatewayJevAdapter`: `createGateway({ apiKey: <OIDC token>, headers: { "ai-gateway-auth-method": "oidc" } })`
  then `experimental_decide({ model: gateway.decision("typesafe-ai/jev"), ... })`. The token comes from
  `@vercel/oidc` `getVercelOidcToken()`; because `apiKey` is always the OIDC token, `AI_GATEWAY_API_KEY` is never
  read (a test sets it and asserts the bearer is still the OIDC token). No token: `ModelError("auth")`, nothing
  sent. Errors map to `billing`, `auth`, `rate_limited`, `invalid_output`, `upstream`, `timeout`; messages are
  scrubbed of bearer values. Every answer is checked again with zod against its question (`checkedAnswers`).
- Three checks, run concurrently (install and docs at once, flagged as soon as scanner findings exist):
  install = one `choice` question per install-surface file (`malicious|suspicious|benign|unclear`) plus four
  `boolean` signals (network, credentials, shell or payload exec, obfuscation); flagged = one `choice` per
  window around a static finding; docs = `declares_no_network`, `declares_pure` (booleans) and `capability_fit`
  (`consistent|mismatch|unclear`). Every question carries the untrusted-data rule.
- Answers become `CheckFinding`s in code: file and line from the slice block the question named, evidence
  pointers (`file:start-end p=0.97`, `rule semgrep <id>`, `install signal credential access p=0.92`),
  severity from verdict plus signals (`severityFor`). A docs declaration counts only when P >= 0.7 and a
  claiming sentence is found in the README or description by regex.
- Readers (`lib/engine/model/readers.ts`) are deleted; stage `readers` is now `checks`; transcript sources
  `jev.install`, `jev.flagged`, `jev.docs`, `luna.report`.

Score (`lib/engine/score.ts`)
- `computeScore` takes sandbox facts (`deriveBehaviour` over forged calls with canary hits, decoy reads,
  persistence writes, processes, dropped datagrams), static hits, OSV intel, Jev findings (`checkFindings`,
  -8 high, -4 medium, reachable files only, deduped with static hits per location) and reputation in its own
  bounded group. `unclear` answers move no points, add a not-verified line naming the location, and block 90+.
  Missing Jev coverage adds "Jev checks did not complete ..." and caps at 89. Verdict words unchanged; no bare
  "Safe"; `not_verified` never empty.

Luna (`lib/engine/model/writer.ts`, `lib/engine/model/openai.ts`)

  failed: the deterministic report is published (`writer: "deterministic"`), still never a bare "Safe".
- Request order: system = `WRITER_SYSTEM` (static, 7,025 characters and 1,140 words, over the 1024-token caching floor with
  the schema), user = per-scan facts JSON, then Jev answers and the stated purpose in UNTRUSTED blocks.

### What was wrong in the forge (found by reading `forge_core.py` and `forge_addon.py`)

Every registry request was fetched by the forge itself with blocking `urllib` in a 32-thread pool on a 1 vCPU VM:

### What was built (general rules)

1. **Package-manager timeouts on the real clock.** The clocks cannot be separated: npm and yarn run lifecycle

   back at its default length in real time: `fetch-timeout` 300 s × 30 and `network-timeout` 60 s × 30, written to the
   install's user npmrc (`/etc/cr/npmrc-install`, where npm and pnpm type them as numbers), plus `YARN_HTTP_TIMEOUT`,
   `YARN_NETWORK_TIMEOUT` and `UV_HTTP_TIMEOUT` scaled the same way. Two dead ends on the way, both seen on real
   scans: scaling the retry waits made pnpm 11 fail at once (`minTimeout is greater than maxTimeout`, it fixes its

2. **A failed root lifecycle script is not a cut install.** When the install exits non-zero and the output shows the
   repo's own `preinstall`, `install`, `postinstall` or `prepare` failed (pnpm `. postinstall: Failed` or `<workdir>
   postinstall: … exit status N`, npm `error path <workdir>` with `command failed`, yarn `YN0009 …@workspace:.`),
   the install is scored as completed and a `root_script` check records it. The report states it under "not
   verified" without reducing coverage. Also: a repo with no entry point (the entry phase is skipped because there
   is nothing to run) or whose entry ran and failed is no longer a "Partial scan"; an entry cut by its time limit
   still is. Both are stated under "not verified".
3. **The install record is not cut.** Before the size cap, `cr-trace-fold.py` folds the package manager's own file

   path, including decoy credential reads. Which process is which comes from the trace: the process that execs a
   package-manager binary and its threads are the package manager; anything it execs that is not one (`sh -c …`) is

   `trace_folded` check records the before and after sizes. Test: package-manager store writes fold, the decoy read,
